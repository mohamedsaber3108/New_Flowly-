## Decisions for the new Flowly

- Positioning: **AI, software & automation. Built around your business.**
- Brand expression: warm cream, vibrant orange, charcoal, restrained sage; a continuous loop as a visual metaphor for connected work.
- Offer architecture: 45 implementation services in eight capability groups, with fourteen audience/industry entry points.
- Conversion: discover needs → describe context → preliminary recommendations → contact → optional consultation request.
- Government: dedicated route and institutional brief, with department, data classification, existing systems, hosting and project reference.
- Commercial model: discovery, build/integrate, operate/evolve; separate costs in scoped proposals.
- Trust: no fabricated customers, testimonials, certifications, delivery timelines, unlimited usage or savings percentages.

## Corrections to the supplied blueprint

The source blueprint is planning material, not proof of operating products or commercially validated claims. Its pricing, model IDs, margins, ROI and delivery estimates were not republished as verified facts.

1. **n8n is not unrestricted open source.** Its [official license guidance](https://support.n8n.io/article/can-i-use-your-license-for-my-use-case) distinguishes implementation from editor access, hosted service and white-label use. Check the actual deployment model.
2. **Dify is not plain Apache-2.0.** Its [official license](https://github.com/langgenius/dify/blob/main/LICENSE) adds conditions for multi-tenant services and frontend branding.
3. **ERPNext is GPLv3.** See the [official open-source documentation](https://docs.frappe.io/erpnext/open-source) and [Frappe license/trademark policy](https://docs.frappe.io/legal/others/license-and-trademark).
4. Tool names are possible building blocks, not Flowly partnerships, production deployments or a guarantee of feature parity. Editions and extensions are selected after fit and license review.
5. Owning custom work, owning data and third-party open-source licensing are different questions; project agreements need to state them separately.
6. Avoid promising unlimited service for a flat fee while model, hosting, messaging or third-party API usage remains variable.
